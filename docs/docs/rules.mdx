# Rules Overview

## Rule Categories

| Category | Description |
|---|---|
| **Best Practices (Nuxt.js)** | Rules for correct composable usage, SSR safety, and Pinia patterns |
| **TypeScript** | Rules for typed props, emits, and repository methods |
| **Directory Structure** | Rules for enforcing Nuxt project architecture conventions |

## All Rules

### Best Practices (Nuxt.js)

| Rule | Description | Type |
|---|---|---|
| [`no-composable-in-class`](./rules/no-composable-in-class) | Disallow Nuxt composables inside class declarations | problem |
| [`async-data-top-level`](./rules/async-data-top-level) | Enforce `useAsyncData`/`useFetch` at top level of setup | problem |
| [`no-async-data-outside-setup`](./rules/no-async-data-outside-setup) | Disallow `useAsyncData`/`useFetch` outside Vue component or composable | problem |
| [`no-direct-api-call-in-component`](./rules/no-direct-api-call-in-component) | Disallow direct API fetching inside Vue components | suggestion |
| [`require-pinia-composition-api`](./rules/require-pinia-composition-api) | Enforce Composition API style for Pinia stores | problem |
